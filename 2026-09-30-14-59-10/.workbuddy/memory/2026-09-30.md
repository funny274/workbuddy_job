## 交付：Spring Boot 3.x 大厂级深度精讲教程站

**产出路径**：`springboot-mastery/index.html`（+ `content.js` 内容数据）

**形态**：单文件 HTML 教程站，左侧可折叠目录树 + 右侧正文，离线可双击打开，无外部依赖（无 CDN、无外网字体）。含进度条、代码复制按钮、面试题折叠卡、滚动高亮当前小节、移动端适配、light 主题。

**章节结构**：
- 第0章 快速复习（SSM→Boot 认知对齐、IoC 三层、AOP 失效、MVC 链路、2.x→3.x 断点、7天路线图）
- Day1 启动原理与自动配置（@SpringBootApplication 拆解、自动配置原理、手写 starter、run() 全流程、配置优先级、debug 实战）
- Day2 Bean 生命周期与源码（12 步生命周期、三级缓存循环依赖、作用域线程安全、手写 IoC 容器）
- Day3 Web 全链路（RESTful 规范、JSR-303 校验、Filter/Interceptor/AOP 选型、跨域与文件上传）
- Day4 数据访问与事务（传播行为、事务失效 8 场景、MyBatis-Plus、HikariCP 调优、多数据源）
- Day5 进阶与可观测性（AOP 三切面、异步线程池、事件机制、缓存三问题、Actuator、日志与链路追踪）

**技术实现要点**：
- 内容与渲染分离：`content.js` 用 `CHAPTERS.push({...})` 注册章节，`index.html` 注入目录树与正文
- 代码块用 `<pre data-lang data-code="URI编码">`，前端 decode + 轻量语法高亮（Java/XML/SQL/YAML/Shell），避免 HTML 转义问题
- **踩坑记录**：用 bash heredoc（`cat >> file << 'EOF'`）追加含 `${}` 的 JS 内容会报 `Bad substitution`；用 Python 原始字符串追加时，若某处 `QA(...)` 缺闭合括号会导致 `Unexpected token '}'`。最终改用 Node 脚本 + `JSON.stringify` 生成已修复段落（归档在 `_build/`）。

**用户背景关联**：用户 12 年后端经验（4年C++/8年Java），本教程定位「面试+实战双拼」，以 Spring Boot 3.x + JDK17 为基准，保留基础复习章并重点覆盖其迁移经验（Oracle→OceanBase/GoldenDB）的面试包装。

## 第二轮：自我审计与修复（用户要求「必须找出初次生成的错误」）

**核心发现（均为初次生成的真实缺陷）**：

1. **【严重】语法高亮占位符机制全面失效**：`highlightJava` 用 `"\u0001"+idx+"\u0001"` 做占位符，但后续「数字正则」`\b\d+\b` 会匹配占位符里的序号数字，把 `\u00010\u0001` 破坏成 `\u0001<span class="num">0</span>\u0001`，导致还原失败 → **全部 39 个 Java 代码块的注释/字符串消失并残留 `\u0001` 乱码**。
   - 修复：改用私有区字符做占位符 `\uE000 + idx + \uE002 + \uE001`（不含数字/单词字符），并在数字正则前加 `[^\w.\uE000]` 负向守卫；统一「所有插入 HTML 全部进 store，最后一步正则整体还原」策略。

2. **【严重】`highlightJava` 双重转义**：stash 时已 escapeHtml，之后又整串 escapeHtml → 注释/字符串内 `<` `&` 变成 `&amp;lt;`。修复：先整串 escapeHtml，再从已转义文本出发匹配 token。

3. **【严重】`highlightXml` 完全错乱**：`(&lt;\/?)([\w:.-]+)` 会把自身生成的 `&lt;span class="ann"&gt;` 里的 `span` 当标签名二次包裹，输出垃圾。修复：同样改为占位符策略。

4. **【中】SQL 转义引号 `'it''s'` 被拆成两个 span**。修复：`'(?:[^']|'')*'` 整体匹配。

5. **【中】YAML 值正则吞掉行内注释**：`enabled: false # 关闭` 整段被当值。修复：逐行处理，识别「未加引号的 #」拆出行内注释为独立 cmt span。

6. **【中】Java 文本块 `"""..."""` 被拆成 3 个字符串**。修复：在普通字符串前先整体匹配文本块。

7. **【内容遗漏】`proxyBeanMethods` / Full-Lite 模式完全缺失**：大厂高频考点，初次生成 0 次提及。已在 Day1 §1.1 补入完整对比表 + 代码示例 + 2 道追问（@Configuration vs @Component、@Bean vs @Component）。

8. **【结构错误】补内容时引入尾随 `+`**：`'...口径。</p>','❓')+` 后直接 `}` → `Unexpected token '}'`（第 278 行）。修复：删掉多余 `+`。

**审计方法（可复用）**：
- 从 `index.html` **提取真实高亮函数**（而非在 `node -e` 里重写）在 Node 沙箱执行，避免转义假象
- 提取 `content.js` 的 `PRE("lang", \`...\`)` **反引号模板**（注意：语言用双引号、代码体用反引号）批量验证
- 用 `new Function(content)` 模拟 DOM 执行，统计 8 章/39 节/**运行期 77 个 pre[data-lang]**（java48/yaml15/bash10/xml3/sql1）
- `node --check content.js` 精确定位语法错误行（比自写扫描器准）
- headless Chrome `--screenshot` 实际截图肉眼复核（已验证高亮渲染正确）

**校验结论**：77/77 代码块渲染 0 异常；`<pre>` 20/20 配对（此前"22/21"是 line 9 JS 注释文本的假阳性）；章节 id 41 个无重复；HTML 结构标签全部配对。审计脚本归档 `_build/`（audit_hl.js / audit_content.js / render_e2e.js / test_yaml.js / cdp_shot.js / shot/）。
